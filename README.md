# 点歌 · nekro-plugin-music

多平台点歌插件，为 [nekro-agent](https://github.com/KroMiose/nekro-agent) 编写。

搜索多平台音源，把候选歌曲渲染成卡片图，选中后以语音 / 文件 / 音乐卡片发出；某种方式失败会自动降级到下一种。

| | |
|---|---|
| 插件标识 | `luoxiQAQ.nekro_music` |
| 模块名 | `nekro_music` |
| 适配器 | OneBot v11（NapCat 等） |
| 市场 | 在 nekro 插件市场搜索「点歌」 |
| 许可 | MIT |

## 功能

- **多平台音源**：网易云音乐，以及聚合音源覆盖的 QQ音乐 / 酷狗 / 酷我 / 百度 / 咪咕 / 荔枝 / 一听 / 蜻蜓。
- **候选卡片选歌**：搜索结果渲染成带封面、时长与序号的卡片图，回复序号即可播放，超时自动取消。
- **七种发送方式**：`音乐卡片` / `签名卡片` / `语音链接` / `本地语音` / `文件链接` / `本地文件` / `文本链接`，按配置顺序级联，失败自动降级。
- **歌词与热评**：`/查歌词 歌名` 渲染歌词图片；指令点歌发送成功后可选附带一条热门评论。
- **AI 自然语言点歌**：对 AI 说「放首歌」「我想听晴天」，AI 会搜索并播放。

## 指令

| 指令 | 说明 |
|---|---|
| `/点歌 [平台] 歌名 [序号]` | 不写平台走默认音源（`/点歌 晴天`）；开头写平台名临时切换（`/点歌 QQ 晴天`、`/点歌 网易云 晴天`）；末尾写数字直接播第几首（`/点歌 晴天 2`） |
| `/查歌词 歌名` | 搜索歌曲并发送歌词图片 |

候选列表发出后，直接回复数字即可选歌，该消息不会唤醒 AI。

## AI 自然语言调用

插件注册了两个沙箱工具，AI 在用户想听歌或要歌词时会自行调用：

| 工具 | 说明 |
|---|---|
| `music_play_tool` | 按歌名（可含歌手）搜索并直接播放第一首到当前聊天 |
| `music_lyrics_tool` | 按歌名搜索并把歌词图片发到当前聊天 |

自然语言点歌**不会**附带热门评论（只有 `/点歌` 指令会），这是刻意的：AI 调用发生在对话中途，附一条评论会打断语境。

## 安装

1. **插件市场**：在 nekro-agent 的插件市场搜索「点歌」安装，会 clone 到 `<DATA_DIR>/plugins/packages/nekro_music/`。
2. **手动**：`git clone` 本仓库到 `<DATA_DIR>/plugins/packages/nekro_music/`。

安装后在 WebUI 里启用插件（新插件默认不启用），并填好下面的配置。

> 插件依赖 OneBot v11 适配器发送语音与文件；其他适配器下只能走文本链接。

## 配置

| 字段 | 默认值 | 说明 |
|---|---|---|
| `DEFAULT_PLATFORM` | `网易点歌` | 《点歌》指令默认使用的平台，13 个平台关键词可选 |
| `NETEASE_API_BASE` | 空 | 网易云 NodeJS API 根地址（[NeteaseCloudMusicApi](https://github.com/Binaryify/NeteaseCloudMusicApi)），留空则不启用网易平台 |
| `ENABLE_TXQQ` | `true` | 启用聚合音源（QQ音乐 / 酷狗 / 酷我 / 百度 / 咪咕 / 荔枝 / 一听 / 蜻蜓，来自 `music.txqq.pro`） |
| `SONG_LIMIT` | `1` | 搜索返回的候选数量，1-20。**设为 1 时直接播放唯一结果、不展示候选列表**（选歌流程需要 >1） |
| `SELECT_MODE` | `image` | `image` = 渲染候选卡片图；`text` = 纯文本列表 |
| `CARD_COLUMNS` | `3` | 候选卡片图每行列数，1-5 |
| `SEND_MODE_1` ~ `SEND_MODE_4` | 本地语音 → 本地文件 → 文本链接 → 不使用 | 发送方式优先级，逐级降级；选「不使用」表示就此结束 |
| `ENABLE_COMMENTS` | `true` | 指令点歌后附带一条随机热门评论（仅网易云音源） |
| `ENABLE_LYRICS` | `false` | 发送歌曲后附带一张歌词图片 |
| `SELECT_TIMEOUT` | `45` | 候选列表展示后等待回复序号的秒数 |
| `SIGN_API_URL` | `https://apii.xianyuw.cn/api/v1/qq-musicArk` | `签名卡片` 方式的接口，返回 `{app, meta, prompt, view}` |
| `SIGN_API_KEY` | 空 | 签名卡片接口的 Key，留空则跳过该方式 |

## 发送方式与实测限制

**群聊**：各方式均可用，推荐 `音乐卡片` 或 `本地语音`。

**私聊**：实测（NapCat）有两条硬限制——

- 私聊**不支持文件上传**，`本地文件` / `文件链接` 必然失败；
- 私聊**音乐卡片会被 NapCat 挂起**，约 30 秒后才超时。

所以私聊建议 `本地语音` → `语音链接` → `文本链接`。默认配置即按「本地语音 → 本地文件 → 文本链接」排列，私聊下会在第二步失败后落到文本链接。

## 依赖与前提

- **网易云音源**：需要一个 NeteaseCloudMusicApi 实例，把地址填进 `NETEASE_API_BASE`（如 `http://127.0.0.1:3000`）。跨境或被墙环境下建议本地部署。
- **聚合音源**：`ENABLE_TXQQ=true` 时直连 `music.txqq.pro`，国内服务器访问更稳。
- **本地语音 / 本地文件**：要求 nekro_agent 与协议端（NapCat）都能读到同一个共享目录（本部署用 `nbcache`），且两边绝对路径一致，否则会降级到其他方式。
- **签名卡片**：需要一个返回 `{app, meta, prompt, view}` 的签名接口，通常要单独的 Key。
